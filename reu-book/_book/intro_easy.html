R as a calculator

First and foremost, R can act as calculator. This can be done in either the script or the console. Note that when you do any programming within the console, it does not automatically save as it does in the script.

2+2
[1] 4
2-2
[1] 0
(2+2)*2
[1] 8
(2+2)*2*2
[1] 16
(2+2)*(2*2)
[1] 16

How to annotate text

When wiritng code, it can be very helpful to leave yourself notes as to what you are doing, thinking, or to communicate with others who may encounter the same script. To accomplish this, we use the # [pound sign]. When you want comment something out, # must preceed the code. You can also annotate at the end of a line by following code with #.

#2+2
2+2 # this adds
[1] 4
Note

The annotation that follows the 2+2 code is not reported in the output becuase R is ignoring it.

Creating objects

How?

The first, and potentially most important, step with naming is which operator(s) to use when assigning names. There are two choices: = [equal sign] or <- [less than with dash]. Generally, of these will yield the same result for naming variables.

x = 1
y <- 2
Note

There are some operations that do not follow this rule. We will cover this more in the future as to when we can, and cannot, use either name-assigning operator.

What can I use as a name?

Numbers

Number values, such as a year, cannot preceed a name. R will ackowledge this as code and it will report an error.

2026_name <- x
Error in parse(text = input): <text>:1:5: unexpected input
1: 2026_
        ^

However, numbers can follow text.

name_2026 <- x

Naming philosophy

As with anything, there are guidelines (which can be ignored) that encourage imformative naming. This will become especially important the further you get into data wrangling and data frame manipulation.

CamelCase

CamelCase, as you can see, follows the concept of combining upper- and lowercase letters to distinguish a name. For example, NewDataFrame is easier to read than newdataframe.

ThisNameIsNice <- thisnameisnotnice

under_score

Another popular naming philosophy is the underscore. Rather than changing the case, you separate_words_with_an_underscore. Again, it goes without saying that this_is_easier_to_read than thisiseasiertoread.

coding_is_hard_enough <- letsnotmakeitharderthanithastobe

How informative should a name be?

When it comes down to it, that is up to the author. R studio (and most IDEs) do an excellent job auto-filling object names. There is something to be said about script cleanliness, but again, this is at the authors discretion. Persaonlly, I aire on the side of short, but imformative names.

For example:

  • new_data_2026 > new_data_frame_with_raw_data_2026

  • loc_x_subset.1 > subset_by_location_x_round_1

Note

As long as you do not start your object name with a number, naming comes at the discretion of the author. However, it is important to consider future use (by you and others).
